# 前端骨架方案

本文档由 frontend-skeleton 流程第 4 步产出, 描述工程骨架的选型, 目录, token 结构, 主题, 国际化, 无障碍, 约束与验收. 视觉取值不在本文档拍板, 由 frontend-router 的设计阶段填入.

## 第一阶段范围

工程骨架本身: 目录与模块边界, token 三层结构与管道, 主题机制, 国际化脚手架, 无障碍基线, 约束 (lint, Claude Hooks, CLAUDE.md). 另按工单 0009 的明确要求交付三栏主界面空壳, 只有布局, 没有业务逻辑. 不含任何业务页面, 条目, 加密, 搜索, 备份, 主密码.

## 工程选型 (已由用户确认)

| 项目       | 选择                                                                                          |

## 目录规划 (相对 `src/renderer/src`)

```text
main.tsx      入口: 引入样式, 调用启动流程
app/          应用装配: 启动流程, 根组件, 三栏布局, 侧栏标题
features/     按领域切分, 每个自包含, 互不引用
  folder-pane/  entry-list-pane/  entry-detail-pane/  search-bar/
  settings-trigger/  preferences-switchers/
components/   跨 feature 复用的 UI: 窗格标题, 空状态
  ui/           Shadcn MCP 引入的组件
lib/          第三方封装与适配层
stores/       zustand 状态
theme/        深色类名同步
styles/       token 与主题
i18n/         渲染进程的语言同步 (html 的 lang 与 dir)
testing/      组件测试支撑, 只允许测试文件引用
```

共享与其它进程:

```text
src/shared/     语言与主题取值, IPC 通道名, 两份语言资源 (单一数据源)
src/main/       preferences/, theme/, i18n/, ipc/, window/ 各一个职责
src/preload/    暴露 preferences 桥
```

依赖方向: `main.tsx` 引 `app`, `app` 引 `features`, `app` 与 `features` 引 shared 层 (`components`, `lib`, `stores`, `i18n`, `theme`), 反向与 feature 之间互引一律禁止.

## token 结构

```text
styles/
  tokens.primitives.css   第 1 层, 只有此文件出现颜色与尺寸字面量
  tokens.semantic.css     第 2 层, 引用第 1 层, 明暗两套, 对接 Shadcn 的语义变量名
  tokens.components.css   第 3 层, 组件特例
  theme.css               汇总, Tailwind @theme 映射, .dark 变体
  globals.css             Tailwind 入口
```

组件与页面只引用第 2, 3 层, 不引用第 1 层, 不写任意值. 真实取值与推导依据见 `docs/设计语言.md`.

## 主题机制

- 状态源是主进程的 `nativeTheme.themeSource` (`system`, `light`, `dark`), 值存 `electron-store`.
- 建窗前先设 `themeSource` 与 `backgroundColor`, `backgroundColor` 取自当前明暗的背景 token, 切换时同步更新, 避免白闪.
- 渲染进程在首次绘制前就按解析后的明暗设置 `.dark` 类名, 之后随主进程的主题变化事件更新.
- 首帧设置: `src/renderer/public/theme-bootstrap.js` 作为阻塞脚本放在 `index.html` 的 head 里, 首次绘制前按系统外观设置 `.dark`; CSP 禁止内联脚本, 所以单独成文件.

## 国际化

- 两份正式资源 `zh` 与 `en`, 另有仅开发用的 `pseudo`, 不进设置界面.
- 默认语言取 `app.getLocale()` (须在 `ready` 之后), 用户选择后存 `electron-store`.
- 消息用 ICU 格式. 布局不写死文字容器宽度, 样式用逻辑方向类 (`ms-*`, `me-*`, `ps-*`, `pe-*`).
- 渲染进程在启动时与每次语言切换后, 把 html 的 `lang` 设为 `LANGUAGE_TAGS` 中的标签 (简体中文为 `zh-Hans`), `dir` 取 `i18n.dir()`; 浏览器据此选字体字形, 读屏软件据此选发音语言.
- 切换类控件 (主题, 语言) 的按钮内容不随界面语言变化 (图标, 语言自称), 名称放无障碍标签与悬停提示, 切换语言时控件宽度不变; 其它文字容器不写死宽度.

## 无障碍基线

- 正文对比度不低于 4.5:1, 大字不低于 3:1, 明暗两套都过.
- 交互元素可键盘到达, 焦点样式取自 token.
- 优先语义标签, 组件带正确 ARIA, 由 Shadcn 的 Base UI 基础提供.
- 状态不只靠颜色区分.

## 约束计划

- 硬约束 (lint): 禁原始颜色与尺寸字面量 (CSS 由 Stylelint, 类名由 ESLint), 组件只引语义层, 禁引 off-limits, feature 隔离与单向依赖 (`eslint-plugin-boundaries`), 禁裸原生交互元素, 禁行内 style, `eslint-plugin-jsx-a11y`, 禁 Tailwind 任意值. 不放宽 `eslint.config.mjs` 既有规则. 规则从 `.claude/frontend-skeleton.json` 派生, 实现在 `tools/eslint/frontend-*.mjs` 与 `stylelint.config.mjs`.
- 软约束 (CLAUDE.md 与注入钩子): 同类 UI 出现 2 次必须抽象, 库里有的优先用库, 组件先于页面.
- 新增文件放 `.claude/` 下: `frontend-skeleton.json`, `hooks/inject-frontend-rules.mjs`, `hooks/verify-frontend.mjs`, `frontend-rules.md`; 项目根新建 `CLAUDE.md`. `.claude/settings.json` 受防护, 执行会话不能修改, 两个钩子的接线片段放在工单产物 `frontend-hooks-settings.snippet.json`, 由用户或编排会话合并.

## 视觉方案

视觉方向, 配色, 字体, 圆角, 动效 token 与三层 token 的真实取值都已在 frontend-router 的设计阶段由用户逐项选定, 成文于 `docs/设计语言.md`; 三栏空壳的布局与切换控件的位置也由用户选定, 实现见 `src/renderer/src/app/app-shell.tsx`.

## 验收标准

1. `npx eslint .` 没有报错.
2. `npm run build`, `npx vitest run`, `npx prettier --check .` 通过, 主题与语言切换有单元测试.
3. 仓库根有 `.mcp.json` 与 `components.json`, 组件由 Shadcn MCP 引入.
4. 有成文的设计语言与 token 定义, 亮暗主题可切换且重启后保留, 切换无白闪.
5. 中英文切换生效且重启后保留, 默认取系统语言, 启动显示三栏空壳.
